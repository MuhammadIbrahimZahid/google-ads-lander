## Project Overview

Phase 5 evolves the lead capture system from a complete analytics measurement pipeline into a Google Ads conversion measurement system.

Phase 1 introduced:

- Conversion journeys
- Session-based conversion tracking
- GA4 events
- Duplicate conversion protection

Phase 2 added:

- Lead collection
- API validation
- PostgreSQL persistence
- Marketing attribution fields

Phase 3 improved:

- Automatic attribution capture
- First-touch attribution
- Conversion-level attribution
- Unified conversion objects
- Stable conversion identifiers

Phase 4 focused on analytics infrastructure.

The application started communicating with Google Tag Manager through a structured Data Layer.

# 5. Enhanced Conversion Architecture

Phase 5 introduces Enhanced Conversions.

Enhanced Conversions improve conversion measurement by sending hashed first-party customer information alongside conversion events. The customer data is normalized and hashed before being sent. ([Google Support][1])

The architecture:

```text
Lead Identity

↓

Normalization

↓

SHA-256 Hashing

↓

user_data Payload

↓

Google Tag Manager

↓

Google Ads Enhanced Conversion
```

# 8. Normalization Layer

File:

```text
src/lib/normalization.ts
```

Phase 5 introduces identity normalization.

## Email Normalization

Rules:

- Trim spaces
- Convert lowercase
- Remove Gmail dots

Example:

```text
John.Smith@gmail.com

↓

johnsmith@gmail.com
```

---

## Phone Normalization

Rules:

- Remove formatting characters
- Preserve country prefix

Example:

```text
+92 300-1234567

↓

+923001234567
```

---

## Name Normalization

Rules:

- Trim whitespace
- Collapse spaces
- Lowercase

Example:

```text
John Smith

↓

john smith
```

# 20. Phase 5 Design Decisions

## Why use Google Tag Manager?

Application code should not directly depend on advertising platforms.

GTM provides:

- Flexible tag management
- Faster marketing changes
- Better debugging
- Cleaner engineering boundaries

---

## Why use Enhanced Conversions?

The system already knows the lead identity.

Instead of sending raw customer information:

```text
Email

↓

Normalize

↓

Hash

↓

Send
```

This creates a privacy-aware matching system.

---

## Why keep conversion IDs?

The same identifier connects:

```text
Browser

↓

Database

↓

Analytics

↓

Advertising Platform
```

This supports:

- Debugging
- Attribution
- Offline conversion expansion
- Server-side tracking
